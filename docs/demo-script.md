## 逐段脚本

### ① 开场 (0:00 - 0:30)

**画面**：Streamlit 首页 + 侧栏展示项目名称 "Novel → Screenplay"
**旁白**：

> "大家好，我是 Frank。这是为七牛云 1024 大赛题目三打造的 AI 小说转剧本工具：Novel→Screenplay。
>
> 很多小说作者想把作品改编成剧本，但从叙事文本到分场对白之间有巨大的结构鸿沟。这个工具调用 DeepSeek 大模型，把 3 章以上的小说自动转为带潜台词、带原著定位的结构化 YAML 剧本，让作者拿到可编辑的初稿直接打磨。
>
> 我接下来用我在这个 repo 里写的一篇原创短篇《守灯人》来完整演示：粘贴→转换→预览→重写→下载。

**关键词**：题目三、结构化 YAML、原创短篇

---

### ② 架构与 Schema 快览 (0:30 - 1:20)

**画面**：切到 `docs/yaml-schema-design.md`，滚动至 §3 三个差异化决策
**旁白**：

> "先花 30 秒讲一下 Schema 设计，因为后面所有演示都基于它。
>
> 第一个决策：我放弃了行业常用的纯文本 Fountain 格式，改用**节拍序列 beats[]**。每个 beat 有 type 枚举——action、dialogue、voiceover、transition。这样 AI 输出不会把动作写成对白、把内心独白写成对话。
>
> 第二个：每条对白带 **subtext 潜台词字段**。小说改编最痛苦的不是写台词，而是让银幕台词有言外之意。原著的心理独白搬不上银幕，这个字段让 AI 帮作者把"没说的话"补出来。
>
> 第三个：每个场景有 **source 追溯字段**——第几章、第几段到第几段。作者打磨时点一下就能跳回原文。这是 AI 生成和人工打磨之间的接缝。"

**关键词**：beats、subtext、source

---

### ③ 主流程演示 (1:20 - 2:30)

**画面**：切回 Streamlit 标签页。逐步操作。

**操作步骤（画面上逐屏对应的内容）**：

1. 侧栏填 meta：标题「守灯人」、原著名「守灯人」
2. 输入区 → 示例 tab → 选 `the_lighthouse_keeper.txt` → 点击「载入示例」
3. 粘贴区自动填入文本，底部显示字符数
4. 点击「🚀 开始转换」→ 进度条走（"转换第 1/3 章…"→"转换第 2/3 章…"→"转换第 3/3 章…"）
5. 完成后自动切换到结果区

**旁白**：
> "粘贴原创短篇《守灯人》，三章，约 1500 字。点击开始转换。进度条按章推进，每章大概 30 秒。
>
> 完成了——4 个场景，校验通过。"

**画面**：
- 展开第一个场景卡片「S001」
- 指到 action beat 的斜体描写
- 指到 dialogue beat 的 **角色名**
- 指到 💭 潜台词那行

**旁白**：
> "场景卡片里能看到：action 用斜体；dialogue 用粗体角色名加对白内容；底下——这个💭就是 AI 抽出的潜台词。比如这句'不必'，AI 读出了主角的心理防线。"

**画面**：
- 切到「YAML 源码」tab
- 滚动展示完整 YAML
- 点击「📥 下载 YAML」

**旁白**：
> "切到 YAML 源码 tab 可以看到完整的结构化输出。确认没问题就下载。"

**关键词**：进度条、4 场景、校验通过、潜台词

---

### ④ 场景级 AI 重写 (2:30 - 3:30)

**画面**：
- 在场景卡片底部，🪄 区域输入重写方向：「让对白更克制」
- 点击「✨ 重写」
- 等待 → 新版出现
- 展示台词变化
- 点击「↩️ 撤销」恢复原版

**旁白**：
> "这是我认为最实用的功能：场景级重写。
>
> 整本重跑要 5 分钟，但作者通常只是对某场戏不满意。在这里，展开场景卡片，底部输入重写方向——比如'让对白更克制'——点重写，只改这一场。
>
> 改了之后如果不满意，点撤销就能回到上一版。这个循环让作者可以逐场打磨，每场 10-20 秒，不用反复跑整本。"

**关键词**：单场景、低延迟、撤销

---

### ⑤ CLI + API 入口 (3:30 - 4:15)

**画面**：切到终端

```bash
$ novel2script convert examples/input/the_lighthouse_keeper.txt \
  -o /tmp/lighthouse.yaml \
  --title "守灯人" --source-novel "守灯人"

[1/1] 解析章节完成，共 3 章
[1/3] 正在转换第 1 章...
[2/3] 正在转换第 2 章...
[3/3] 正在转换第 3 章...
[完成] 已写出 /tmp/lighthouse.yaml（4 个场景）

$ head -30 /tmp/lighthouse.yaml
```

**画面**：快速切到浏览器 → `http://localhost:8000/docs` → 展开 `POST /convert` → 展示请求体 → 展示响应 → 再展开 `POST /refine`

**旁白**：
> "除了 UI，还有 CLI——一行命令跑完全流程，适合批量转换。
>
> 另外还提供了 HTTP API：`POST /convert` 和 `POST /refine` 两个端点。别人如果想做自己的前端，直接调 API 就行——FastAPI 的 Swagger 文档一目了然。"

**关键词**：CLI、API、Swagger

---

### ⑥ 收尾 (4:15 - 5:00)

**画面**：切回 Streamlit 首页

**旁白**：
> "回顾一下这个工具的三个差异化亮点：
>
> 一是节拍序列 beats，让 AI 输出结构严谨、可校验；
> 二是潜台词字段 subtext，AI 帮作者补出言外之意，这也是改编最难手写的部分；
> 三是可追溯 source 字段，每个场景对应原著位置，作者可以直接跳回原文打磨。
>

>
> 谢谢观看。"

**画面**：最后停 3 秒在 README 仓库 URL 上
